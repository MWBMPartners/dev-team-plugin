### 1. (medium) The lookup order moves and commits a marked legacy-root file, but several read-only commands and phases now say they use it while promising to change nothing

- **Where:** `skills/dev-team-orchestrator/references/conventions.md` line 95
- **What is wrong:** Point 5 of the ownership section says a legacy-root file that carries a marker is `git mv`'d into `.dev-team/`, re-stamped and committed "before any other work" on "the current run branch". The only exception written down is dry-run. But this branch now tells read-only callers to find their ledger "through the lookup order (point 5)": `/dev-team-status` (commands/dev-team-status.md:6, whose line 4 says "CHANGE NOTHING on disk"), `/dev-team-report` (commands/dev-team-report.md:14, whose line 10 says it "never creates, edits, or touches any file" and never runs a mutating git command), `/dev-team-approve` (commands/dev-team-approve.md:8, which may only edit one field of autopilot.json), the review skill's verification phase (skills/dev-team-review/SKILL.md:49, while line 22 says "The verification phase changes nothing"), docs `audit` mode (skills/dev-team-docs/SKILL.md:144, "No draft, no fix, no commit") and ci-medic (skills/dev-team-ci-medic/SKILL.md:49). None of these has a "run branch" to commit on. The two instructions cannot both be followed.
- **How it goes wrong:** A repo on `main` has a pre-1.5.0 top-level `PROJECT.md` with `<!-- dev-team-schema: 1.0 -->` on line 2 and no `.dev-team/PROJECT.md`. The user runs `/dev-team-status` to look at the dashboard. Reading point 5 literally, the command `git mv`s the file, rewrites its marker and makes a commit on `main` (the branch that is checked out) from a command documented as read-only, with no run branch and without asking. Alternatively the agent honours "CHANGE NOTHING" and then has no instruction for what to read, and may guess.
- **Proof:** conventions.md:95: "**Legacy root file with a marker** (either form) → it is ours. `git mv` it into `.dev-team/`, rewrite the marker to the new form, and commit that on the current run branch ... before any other work. Under dry-run, read it where it is, move nothing, and report the move as pending."  commands/dev-team-status.md:4: "Print a concise, read-only dashboard ... CHANGE NOTHING on disk."  commands/dev-team-status.md:6: "If `.dev-team/PROJECT.md` is found through the lookup order (... point 5 ...)".  commands/dev-team-report.md:10: "command is **read-only**: it never creates, edits, or touches any file, and never runs `git fetch` or any other network/mutating git command."  commands/dev-team-report.md:14: "through the lookup order (`conventions.md`, ... point 5)".
- **Fix:** Add a read-only clause to point 5 next to the dry-run one: a read-only command or phase (status, report, approve, review's verification phase) reads a marked legacy-root file where it is, moves and commits nothing, and reports the move as pending with a pointer to /dev-team-move-ledgers. Also say which branch a writing skill commits the move on before its run branch exists. docs audit and ci-medic can stay as they are, because they already write.
- **Refuter's confirmation:** I confirmed the clash in the text. In conventions.md point 5 (line 95), finding a marked file at the top level means the reader must move it with `git mv`, update its marker and commit it on the current run branch. The only exception written there is dry-run. Several callers that promise to change nothing are pointed straight at point 5: dev-team-status.md step 2 (its line 4 says CHANGE NOTHING on disk), dev-team-report.md step 1 (which never touches a file), dev-team-approve.md step 3, and the review skill's step 1 (its verification phase changes nothing). The two instructions cannot both be followed. The damage is smaller than the finding says, though. Status step 4 already says legacy files are only reported, never moved.
