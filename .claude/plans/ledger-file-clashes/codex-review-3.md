1. **High — Mixed ledgers can be misclassified and moved.** [commands/dev-team-move-ledgers.md:25](</Users/lance.manasse/Projects/Coding & Development/MWBM Partners Ltd/GitHub/dev-team-plugin/commands/dev-team-move-ledgers.md:25>) says the first matching test wins, but the broad “looks like ours” tests at lines 34–41 run before the mixed-file test at lines 45–47. 2. **High — An ignored legacy source can leave a partly completed move.** [commands/dev-team-move-ledgers.md:19](</Users/lance.manasse/Projects/Coding & Development/MWBM Partners Ltd/GitHub/dev-team-plugin/commands/dev-team-move-ledgers.md:19>) relies on `git status --porcelain`, which does not show ignored files. The ignore preflight at line 66 checks destination paths, but never confirms that each source is tracked. For example, a root-only `/SECURITY.md` ignore rule can hide a marked, untracked `SECURITY.md` while `.dev-team/SECURITY.md` remains unignored. Step 4 can create support files and earlier moves can succeed before `git mv SECURITY.md ...` fails because the source is not tracked. The rollback instruction at line 110 applies only to failures in steps 8 or 9, so this leaves a half-moved tree. Before changing anything, require `git ls-files --error-unmatch -- <source>` for every move and make failures in every write step, including steps 4–7, enter rollback.

3. **High — The rollback can erase unrelated work created after the initial clean check.** [commands/dev-team-move-ledgers.md:110](</Users/lance.manasse/Projects/Coding & Development/MWBM Partners Ltd/GitHub/dev-team-plugin/commands/dev-team-move-ledgers.md:110>) says `git reset --hard HEAD` is always safe because the tree was clean when the command began. Questions are asked between that check and rollback, so an editor, formatter, hook, or another process can create tracked changes during that interval. A later marker or commit failure then permanently deletes those changes. This is a data-loss risk. Record exactly which paths and original contents the command changes and restore only those; at minimum, recheck for unrelated changes before rollback and stop for manual recovery instead of running `reset --hard`.

4. **Medium — The no-move decline path can write an ignored config and fail without cleanup.** [commands/dev-team-move-ledgers.md:66](</Users/lance.manasse/Projects/Coding & Development/MWBM Partners Ltd/GitHub/dev-team-plugin/commands/dev-team-move-ledgers.md:66>) omits `.dev-team/config.yml` from its ignore preflight. If the project ignores `.dev-team/config.yml`, `git add` fails after the file has been created, and the rollback section does not cover this standalone path. Include config in the preflight whenever the pointer question might create or modify it, and give the standalone commit path the same rollback guarantees as the move path.

5. **High — Starting the session in a repository subdirectory bypasses Rule 2.** [hooks/guard-ledgers.sh:167](</Users/lance.manasse/Projects/Coding & Development/MWBM Partners Ltd/GitHub/dev-team-plugin/hooks/guard-ledgers.sh:167>) treats the payload’s `cwd` as the project root.
